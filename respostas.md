# Respostas da atividade

1. O envio não cai na listagem porque o formulário usa POST, enquanto a listagem aceita GET. O Spring diferencia as rotas pelo caminho e pelo método HTTP. Sem a rota POST, o envio recebe HTTP 405 (método não permitido).

2. No projeto original, o MySQL atribui o id automaticamente porque a coluna foi definida como AUTO_INCREMENT na migração da Semana 6. Na adaptação solicitada para PostgreSQL, a definição equivalente usada é GENERATED BY DEFAULT AS IDENTITY, que também faz o banco gerar o id.

3. A validação deve ocorrer antes de salvar para impedir que dados inválidos sejam persistidos. Se o banco aceitar o dado inválido, ele permanecerá gravado mesmo que a validação posterior apresente um erro, exigindo correção ou remoção.

4. No cenário do desafio opcional, as sugestões são gravadas e consultadas no banco, que mantém os registros após o reinício da aplicação. Na Semana 3, elas ficavam em uma lista na memória do processo e eram perdidas quando ele encerrava. O desafio opcional não foi implementado nesta entrega; a listagem em memória foi mantida conforme a missão 4.1.
